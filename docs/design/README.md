# Design Docs

_Last updated: 2026-05-02_

These docs explain subsystem design choices and rationale. Use them when you need intent, trade-offs, or historical design context for a specific feature.

Design docs should describe the stable rationale after a change lands. Temporary audit punch lists and implementation cleanup notes should live in `../todos/`, `../issues.md`, or `../proposals.md`, then be folded back here only when the resulting behavior is current.
