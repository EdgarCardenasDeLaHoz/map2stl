# Full code audit — 2026-10-05

Line-by-line read of the whole application and its mesh library (map2stl at `8ac3b29` and
`numpy2stl` HEAD), done in a cloud session by eight parallel reviewers, one slice each. Every
"dead" claim was grepped across both repos, tests, tools and notebooks. Every high-severity
bug was reproduced or re-read before it was listed. Line counts are estimates of what
could be deleted outright. This is a snapshot: fixes move to [issues.md](../../issues.md) /
[issues-resolved.md](../issues-resolved.md), and work items to the plans.

About 14 % of the production code can be deleted, plus about 11k lines of tools and tests. 8.7k of those are legacy ML training code that the approved proposal ML-3 already covers. Two themes:

- **Most of the bloat is research and diagnostics left in production paths.** It comes in four kinds:
  - skyline experiments behind flags that default off;
  - report-only computation inside the per-seed loop;
  - notebook-era SDK methods that crash on today's payloads;
  - CNN and roof-classifier tiers with no checkpoint.
- **Small defects repeat across modules**: several copies of the same helper drifting apart, caches with keys or atomicity wrong, silent fallbacks. In total:
  - three Overpass clients;
  - three river rasterizers;
  - seven km-per-degree helpers with three constants;
  - three `simplify_tolerance` defaults;
  - four projection-math copies in skyline.

## 1. Backend (`app/server`, `app/session`)

**Bloat** (~1,250 high-confidence):
- `terrain_session.py::check_alignment` and its helpers are dead and broken: they read `dem_values`, but the payload only has `dem_values_b64` (~430).
- `core/cache_inspector.py` and `/api/cache/inventory` have no consumer (~380).
- `core/height/train.py` trains a U-Net on all-zero RGB tiles and writes its outputs outside the repo (~300).
- The `merge_hydrology` route plus the SDK method can never succeed: its cache key omits `cache_extra` (~160).
- The sync `generate_stl/obj/3mf` export routes duplicate the async pipeline; only tests use them (~110).
- `terrain.py`:
  - the trails / Natural Earth payload dicts are written 5× and 3× (~90);
  - every route declares `Query` params and then re-parses `request.query_params` (~70);
  - pass-through wrappers cite a non-existent `core.projection` (~40).
- `cities.py::get_city_raster` uses a hand-rolled MD5 cache in the `dem` namespace (~35).
- Small duplicates (~70): `model_to_dict` ×3, `_bed` ×2, the 3MF writer ×2, `run_server`.

**Bugs and risks**:
- **Upload read.** `upload_mesh` reads the whole file before the 200 MB check, and the save runs synchronously on the event loop.
- **SDK methods that fail on today's payloads.** `fetch_building_heights` raises KeyError, `rasterize_city` always gets a 422, `predict_heights` always crashes, and `_validate_list_layers` rejects 6 of the 9 layers.
- **`osm_*` composite channels come back as zeros.** `composite.py` and `cities.py` read OSM at the 0.5 m tolerance while the panel fetches at 3.0 m.
- **Three `simplify_tolerance` defaults** (0.5 / 2.0 / 3.0), and the SDK uses dim 800 against 600 elsewhere.
- **`get_city_raster` serves stale rasters**: its cache key ignores the posted features.
- **Blocking work on the event loop**, breaking CLAUDE.md rule 7:
  - `get_terrain_dem`: projection, payload, `savez`;
  - `diagnostics`: `rglob` over the cache;
  - `auth_status`: Earth Engine init;
  - `get_city_raster`, `height_fetch`, the reports scans.
- **`composite._single_flight`** blocks executor threads on a lock.
- **`clear_bbox_cache`** ignores its bbox and wipes every namespace.
- **`config.json` writes** are an unlocked read-modify-write.
- **DEM passed as Python lists**: export turns the grid into about 4M Python floats per 2000² export.

**Pipelines**:
- **Terrain:** the cache design is good (one key owner, projection kept out of the key, the `dem_id` handle). Wrap "project + payload + cache write" in one `run_sync`, and share one `_raster_route` helper across the five copied route skeletons.
- **Composite:** `compute_composite_dem` (~220 lines) lives in a router that `core/export_params` imports, which inverts the layering. Move it to `core/composite.py`.
- **City:** route every OSM read through `lookup_city_layers`, using the client's tolerance.
- **Export:** the two-stage design is good. Drop the sync routes and keep the DEM as an ndarray in `ExportContext`.
- **SDK:** delete the broken methods and split out the plotting helpers. The 3k-line class is mostly notebook residue.

## 2. Frontend ES modules (`app/client/static/js/modules`)

**Bloat** (~1,300):
- `layers/hydrology-overlay.js` renders a canvas nothing reads, but runs on every `loadAllLayers`, so each bulk load sends a second `/hydrology` request (~225).
- The `compare-view.js` view and the region-table view cannot be reached (~245).
- The satellite fallback in `dem-main.js` cannot be reached (~125).
- `water-mask.js::renderCombinedView` colours the DEM pixel by pixel into a hidden pane (~100).
- Handlers bound to ids that no longer exist, in app-setup, event-listeners-map, view-management, bbox-panel and city-render (~280).
- `city-overlay.js` computes `terrain_z` and nothing reads it (~55).
- `composite-dem.js` keeps `compositeFeatures`, eight DEM-sized arrays, and never reads them (~26).
- Seven km-per-degree helpers with three constants (~30).
- In `cache.js`, the "LRU" cache is actually FIFO.
- About 15 stale "plain `<script>`" docstrings.

**Bugs and risks**:
- **`dem-main.js::renderDEMCanvas` re-announces the DEM.** It runs on every recolour and on every frame of a panel resize. Each call replaces `lastDemData` without `bbox`/`sourceDimensions`, emits `DEM_LOADED` and triggers a model rebuild. As a result:
  - the city raster gets projected twice;
  - empty layers are refetched;
  - every building is redrawn.
- **Aborted requests show red error toasts**, because `api.js::_fetch` turns `AbortError` into an `{error}`.
- **Bbox inputs have three keydown handlers.**
  - An arrow key moves the value by 0.11°.
  - Enter runs `loadDEM` and `loadAllLayers` together.
  - Edits are written into the saved region.
  - A mini-map drag reloads the previous area.
- **`map-globe.js::initGlobe` is not idempotent**: each toggle creates a new WebGL context.
- **Selection race in `regions.js::selectCoordinate`**: selecting A then B quickly can autosave A's settings under B.
- **Curve editor**: spreads the Float32Array, using about 8× the memory and turning the values into a plain Array.
- **Thumbnails are always blank.**
- **`enhanceBuildingHeights`** drops `_cityIndex`, which breaks selection and the height overrides.
- **Export** dereferences null after a failed preview.

**Pipelines**:
- **Explore:** add a selection token checked after each await, and route every bbox write through `setBboxRectangle`.
- **Edit:** split `renderDEMCanvas` into a pure renderer plus a `setDem()` that is the only place `DEM_LOADED` is emitted. Coalesce `STACKED_UPDATE` into one rAF.
- **Composite:** compute from an immutable base DEM. Today rivers get carved twice in the preview.
- **Extrude:** send the preview as binary typed arrays and colour it with a LUT.
- **City:** delete the `lastDemData` listener, which invalidates every city cache on each change.

## 3. Frontend Vue (`app/client/static/js/vue`, templates, CSS)

**Bloat** (~1,450):
- Unused runtime payloads:
  - `index.html` loads Plotly 2.29 from a CDN (~3.5 MB per page load) and nothing uses it;
  - PrimeVue, its Aura theme and primeicons are installed and configured but no component uses them.
- About 750 lines of dead `app.css` rule blocks.
- About 410 lines of scoped CSS and markup in sections that are hidden or unreachable.
- Write-only store keys and unused bridge/store actions.
- `ModelContainer.vue` keeps copies of the `dom-fields.ts` helpers.
- Watchers that never fire: `CityBuildingsPanel`, and the search watchers.

**Bugs and risks**:
- **Status users can no longer see.** F-EDITPANEL left these inside the hidden `#legacyControls`, so users never see them:
  - `CityFetchProgress`, including its **Cancel** button;
  - the "OpenTopography key not configured" warning;
  - the sampling info, resolution warnings and composite stats.
- **Two city-size limits**: the city table allows 10 km where the panel allows 25 km.
- **About 30 appState keys are not declared in the store.**
  - Their large payloads become deeply reactive.
  - Their initial values are dropped.
  - `sidebarState` and `sidebarMode` duplicate each other.
- **Bridge semantics**: `off()` removes every watcher on the key, `on()` is shallow, and there are no tests.
- **The DOM is the source of truth.** It is kept fresh by a `tick` counter, a 1.5 s `setInterval` poll and two capture-phase listeners.
- **Accessibility:**
  - collapsible headers are `div`s;
  - several lists are click-only, with no keyboard access;
  - the modals have no `role="dialog"`, Esc handling or focus trap.

**Architecture**:
- F-FE1 has drifted into a third model: Vue owns the markup, and the data model is about 150 hidden control ids.
- Next step: F-FE1 step 3 for the Edit panel. Add a typed `settings` store keyed by control id, with `dom-fields.ts` as the only adapter. That removes the tick, the poll and the capture listeners, and lets the hidden status move into FETCH.
- Cheap guard to add first: a dev-mode warning in the bridge's `set` trap for undeclared keys.

## 4. Skyline core + pano (`city2stl/skyline/_core`, `_pano`, depth, coastline, cross-view)

**Bloat** (~1,530):
- Flag-off experiments:
  - F-SKY19/20/21 multires (~365, and broken: a 3-tuple is unpacked as 4);
  - F-SKY5 MobileSAM (~170, a README dead end);
  - F-SKY16/18-3 ICP, which only writes log lines (~225);
  - F-SKY10 `cross_view.py` (~350; half its score is constant across candidates);
  - the F-SKY24 depth post-cut (~95, measured as a no-op).
- Six copies of the projection math.
- The bearing cross-correlation exists twice with different gates.
- Unused loggers with a wrong comment in seven `_core` modules.
- Stale docstrings: kernel size, "SegFormer-b0", "Phase A no impact", floor-period divisor.
- **Report-only work:** `effective_height_m` comes only from `estimate_heights_from_registration`. These never reach a height: segmentation stages 3–8, segment matching, rescue, smoothing, and all of Pass 3 (stitching, tiled DA2, bearing xcorr, the sliding splitter). That is about 1,500 lines and most of the per-seed time. Gate them behind `SKYLINE_CV_HTML_REPORT`.

**Bugs**:
- **Hole-fill flood.** `_neural_sky_and_building_masks` seeds `floodFill` at (0,0). When the top-left pixel is building, every non-building pixel is promoted (verified: 8100 of 8100). The contour then falls back to h/2, with no error.
- **Roof-to-building assignment.** Each footprint takes the top row of the *union* building mask. A low-rise in front of a tower gets the tower's roof, and the tower itself is gated out. This matches the measured Miami bias: towers −59 m, low and mid-rise +29 to +42 m.
- **Bearing correction never reaches heights**, so Chicago's 180° error stays in its heights. A 360° anchor sweep for road panos invites the 180° twin.
- **Stale vertex cache.** `_get_vertex_arrays_cached` is keyed on `id(list)` without holding a reference, so stale geometry can come back after GC.
- **Floor period.** `_floor_period_for_building` keeps the largest divisor, not the smallest.
- **Depth.** Calibration differs between the per-view and pano paths. The F-SKY12 downweight never reaches `effective_height_m`.
- **Vertical focal length.** It hard-codes a 75° FOV and uses image height. Camera height is 1.7 m here but 2.5 m in the depth path.
- **Seed cache location.** `_pano/runs/seed_resolution_cache.json` is git-tracked and sits outside the gitignored `skyline/runs/`, so the README cache is ignored.
- **Silent excepts** wrap hundreds of lines.
- **The occlusion penalty is O(S·P²)**.

**Verdict.** On the Miami plate the panorama pipeline scores MAE about 60 m with corr 0.12. Google 3D Tiles scores 14 m with corr 0.92. Recommendation:
- Use satellite and lidar as the default height sources.
- Keep skyline as a fallback for uncovered areas and as a heading demo.
- Freeze skyline feature work until the F-SKYBENCH baseline exists. Then fix assignment and the flood fill, and cut the report-only paths.

**Bugs**:
- **Satellite footprint areas.** `satellite_footprints.py::merge_satellite_into_osm` stores areas in deg² (about 1e-7), so every `ms_*` record gets a 0.6 m height proxy. Confirmed by running it.
- **Wasted Street View quota.** Auto-proposals that screen as ERROR or IMAGE_FAIL count as "weak", not "rejected", so they still get full 12-view registration: up to about 36 billed requests per dead point.
- **Images from the wrong place.** `_streetview_image` widens the radius to 1.5 km without checking metadata.
- **Web seeds:**
  - always on, with no flag;
  - a hard-coded FOV;
  - `return` instead of `continue` drops the rest of the batch;
  - uncached search, so runs aren't reproducible.
- **The screen cache key** leaves out the model and thresholds. **The MS tile download** is non-atomic.
- **Misleading plots.** The reconstruction plot overwrites distances beyond 1200 m with OSM truth, so it agrees by construction. The bearing-scan verdict is recomputed rather than read from the pipeline.
- **Silent JSON failures.** A malformed site JSON becomes `{}`, and a failed elevation fetch becomes 0 m.

**Pipelines**:
- The reporting layer (~6.5k lines) is bigger than orchestration (~2.5k).
- Make benchmark runs hermetic. This commit pins the flags; still to do:
  - a web-seed flag;
  - record the site flags in `summary.json`;
  - put the model in the screen-cache key;
  - fix the MS area bug.

  Then run the baseline, and cut any reporting not tied to a benchmark metric.

- **EPT nDSM** has no noise filter. **`train.py`** turns off augmentation for the training split too.
- **Road widths** are buffered in degrees, so north–south widths are inflated by 1/cos(lat).

**Pipelines**:
- **OSM:** one Overpass client in geo2stl.
- **Heights:** sample each provider per footprint (zonal median) instead of one 512² raster plus the centroid pixel. Then retire the four API-only providers.
- **Roofs:** trim to the GBM.
- **City model:** add the style to `polygons_key`.
- **Registration:** build the map rasters from the shared OSM payload, using `height_from_tags`.
