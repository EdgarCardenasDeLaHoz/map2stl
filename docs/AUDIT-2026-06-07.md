## Part 2 — Bloat findings (ranked)

### 🔴 1. Git line-ending churn makes the working tree look fully rewritten
`git status` reports **80+ files modified**, but `git diff --ignore-all-space`
is **empty** — every diff is pure CRLF↔LF noise. Cause: `core.autocrlf=true`
with **no `.gitattributes`** and the repo living inside OneDrive.

**Impact:** `git status` is unusable for spotting real work; any commit risks
sweeping in a whole-repo line-ending rewrite.

**Fix:** add a `.gitattributes` pinning text files to LF (`* text=auto eol=lf`
plus binary rules), then `git add --renormalize .` in one dedicated commit.
This is the single highest-leverage hygiene fix in the repo.

### 🔴 2. `runs/` is 1.1 GB of generated artifacts on disk
`city2stl/skyline/runs/` is **gitignored** (good — not in history) but holds
1.1 GB locally, much of it under `runs/height_traces/_unused/` (hundreds of
per-view minimap PNGs). On a OneDrive-synced tree this is a sync burden.

**Fix:** safe to delete `runs/height_traces/_unused/` and stale
`runs/cartagena_run*.log` (5 logs). Consider a `make clean-runs` target.

### 🟠 3. Three oversized source files
| File | Lines | Largest function |
|---|---|---|
| `region_pdf.py` | **6,524** | `_render_pdf` (556), `_register_views` (436), `_recover_pano_heading` (431) |
| `pipeline.py` | **4,124** | `estimate_heights_from_registration` (458), `detect_buildings_from_mask` (320) |
| `html_report.py` | **2,816** | `render_seed_page` (305), `_render_pano_reconstruction_png` (303) |

`region_pdf.py` mixes four concerns (Street-View I/O, seed selection,
orchestration, PDF rendering). The cleanest extraction would split the PDF
**rendering** functions (`_render_pdf`, `_render_seed_view_page`,
`_render_stitched_pano_page`, `_draw_*`) into a `region_pdf_render.py`,
leaving orchestration behind — mirrors the existing `html_report.py` split.
Not urgent (tests are green and it's actively churning), but it's the top
refactor candidate once skyline feature work settles.
